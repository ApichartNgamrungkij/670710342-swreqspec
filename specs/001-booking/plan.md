# Plan: จองคิวตรวจสุขภาพ (Booking)

- Spec ID: SPEC-BKG-001
- ไฟล์อ้างอิง: `specs/001-booking/spec.md`
- ขอบเขต: UC-01 เท่านั้น

## 1. สรุปแนวทาง

1. ผู้รับบริการที่ผ่านการยืนยันตัวตนเลือกแพ็กเกจ วัน และช่วงเวลาตรวจสุขภาพ (FR-BKG-01, FR-BKG-06)
2. ระบบตรวจคิวเดิมและป้องกันการจองซ้อนก่อนบันทึกการจอง (FR-BKG-02, FR-BKG-03)
3. ระบบบันทึกการจอง ตัดที่นั่ง ออกหมายเลขคิว และล็อกที่นั่งเมื่อเข้าสู่หน้าชำระเงิน (FR-BKG-04, ASM-03)
4. ระบบส่งข้อความยืนยันแบบ asynchronous และ retry เมื่อส่งไม่สำเร็จ (FR-BKG-05, IF-NOT-01, NFR-REL-02)
5. ระบบบันทึก audit log และตรวจคุณภาพตาม AC/NFR โดยไม่ครอบคลุมการชำระเงินจริง (DOM-PDPA-01, NFR-PERF-01, NFR-SEC-01, NFR-USE-01)

## 4. API / หน้าจอ

- `GET /booking/availability` รับแพ็กเกจและช่วงวัน, ส่งวัน ช่วงเวลาที่ว่าง และจำนวนที่นั่งคงเหลือ (FR-BKG-01)
- `GET /booking/availability?package_id=...` รับแพ็กเกจใหม่, ส่งช่วงเวลาว่างที่คำนวณใหม่ (FR-BKG-06)
- `POST /booking/validate` รับ HN วัน และช่วงเวลา, ส่งผลตรวจคิวเดิมหรือผลตรวจพร้อมจอง (FR-BKG-02)
- `POST /booking/confirm` รับ HN แพ็กเกจ ช่วงเวลา และผลยืนยันตัวตน, ส่งรหัสการจอง หมายเลขคิว และสถานะที่นั่ง (FR-BKG-03, FR-BKG-04)
- `POST /booking/payment-session` รับรหัสการจอง, ส่งสถานะล็อกที่นั่งและเวลาหมดอายุ 5 นาที โดยไม่ดำเนินการชำระเงินจริง (FR-BKG-04, ASM-03)
- `POST /notification-retries/process` รับรายการส่งที่ล้มเหลว, ส่งสถานะรอบส่งและเวลาส่งครั้งถัดไป (FR-BKG-05, NFR-REL-02)
- หน้าจอเลือกแพ็กเกจ/วัน/ช่วงเวลา แสดงที่นั่งคงเหลือและตัวเลือกใหม่เมื่อช่วงเวลาเต็ม (FR-BKG-01, FR-BKG-03, FR-BKG-06)
- หน้าจอผลการจอง แสดงหมายเลขคิวแม้การส่งข้อความไม่สำเร็จ (FR-BKG-04, FR-BKG-05)

## 7. ลำดับงาน

1. ยืนยัน `Q-01` และ `Q-02` ก่อนล็อกกติกาช่วงเวลาใกล้เคียงและหมายเลขคิว (FR-BKG-03, FR-BKG-04)
2. ออกแบบ entity และกติกาความสอดคล้องบน MySQL โดยไม่เก็บเลขบัตรประชาชน (CON-TECH-01, IF-HIS-01)
3. สร้างการตรวจ IDP/HIS และ audit log ก่อนเข้าถึงข้อมูลผู้รับบริการ (IF-IDP-01, IF-HIS-01, DOM-PDPA-01)
4. สร้างการค้นหาช่วงเวลา การเปลี่ยนแพ็กเกจ และการตรวจคิวซ้ำ (FR-BKG-01, FR-BKG-02, FR-BKG-06)
5. สร้างการยืนยันการจองและป้องกันการจองซ้อน พร้อมทดสอบ `AC-BKG-01`, `AC-BKG-02`, `AC-BKG-03` (FR-BKG-03, FR-BKG-04)
6. สร้างการล็อก/คืนที่นั่ง 5 นาทีและหน้าสถานะการเข้าสู่หน้าชำระเงิน โดยไม่สร้างการชำระเงินจริง (FR-BKG-04, ASM-03)
7. สร้าง asynchronous notification และ retry 3 นาที รวมไม่เกิน 4 รอบ พร้อมทดสอบ `AC-BKG-04` (FR-BKG-05, IF-NOT-01, NFR-REL-02)
8. ตรวจ NFR และรันทดสอบ `AC-BKG-05`, `AC-BKG-06` รวมถึง TLS และ usability (NFR-PERF-01, NFR-SEC-01, NFR-USE-01)

## 8. สิ่งที่ยังไม่ทำ

- `Q-01` "ช่วงเวลาใกล้เคียง" นับเฉพาะวันเดียวกัน หรือรวมวันถัดไปด้วย? -> ถามพยาบาลคัดกรอง
	ส่วนที่เกี่ยวข้องกับการเลือกและเรียงลำดับ 3 ตัวเลือกจะยังไม่สร้างจนกว่าจะได้คำตอบ
- `Q-02` หมายเลขคิวรีเซ็ตรายวัน หรือนับต่อเนื่อง? -> ถามเจ้าหน้าที่เวชระเบียน
	ส่วนที่เกี่ยวข้องกับกติกาการรีเซ็ตและการนับหมายเลขคิวจะยังไม่สร้างจนกว่าจะได้คำตอบ
